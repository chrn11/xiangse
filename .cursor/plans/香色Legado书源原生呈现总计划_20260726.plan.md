# 香色 Legado 书源原生呈现总计划

> 日期：2026-07-26（修订：同日 G6/`72a6ed8` 真机闭环后回写）
> 本计划是**唯一有效工作指令**。任何 agent 开工前必须先读本文件；与本计划冲突的历史计划、假设链、临时想法一律让路。
> 历史总计划：`.cursor/plans/原生阅读闭环重建_b9167d21.plan.md`（阶段 1–3 的取证与硬规则全文仍以它为准，本计划继承其 12 条硬规则）。

## 一、最终目的

让**香色闺阁（iOS，`com.appbox.StandarReader`，2.56.1）支持 Legado（阅读）书源协议**，且呈现层**全部由香色原版私有 UI 完成**（书架/搜索列表/目录/阅读内核 `TextReadVC3`/分页/滚动/字体/排版/缓存/进度/工具栏）。

**双源并存（硬目标）**：同一安装上，**香色原生 XBS 书源**与 **Legado JSON 书源**同时正常使用——导入/搜索/站点管理/检测/目录/正文/换源等互不替换、互不吞掉对方数据；原生功能不被 Bridge Hook 破坏。形态公式：**Legado 协议 = 数据后端；香色 = 宿主 UI**（含 XBS 与 JSON 两条数据入口，一套原生 UI）。

用户视角的完整闭环：导入 Legado 书源 JSON → 搜索 → 详情 → 目录 → 点章 → **看到的是香色原版阅读 UI** → 翻页/切章/退出再进能恢复 → 书源可管理/可换源/可发现/可净化/可登录；同时原有 XBS 源与本地书仍走同一套原生 UI → **全程感觉不到 Legado 的另一套壳，只觉得「香色能看的书变多了」**。

**不是用 Legado 自己的 UI，更不是 overlay/probe 冒充。**

## 二、范围：做什么 / 不做什么

### 做的（书源功能全集）

| 功能域 | 内容 | 承载体 |
|---|---|---|
| 书源导入 | JSON 单源/数组、「打开方式」分享、`legado://import` 深链、网络 URL | `LBImportHooks` + `SourceRegistry`（UIAlert 过渡 → 阶段七目标：原版导入入口） |
| 书源管理 | 列表/启停/删除/分组筛选/发现入口，持久化重启保留 | `LBLegadoSourceManagerVC`（过渡）+ `legado_bridge_sources.json` → 阶段七目标：原版站点管理承载 |
| 搜索 | 多源搜索，结果注入宿主搜索 UI | `LBSearchHooks` + `dNotifyName_SearchBookSourceResponse` |
| 详情/目录 | 详情解析、目录（含分页/AllInOne），注入宿主目录链 | `LBReadingHooks` + `LBLegadoCatalogListVC`（过渡）→ 阶段七目标：原版 BookDetail/Catalog 链 |
| 正文 | 正文抓取灌入原版阅读内核，缓存/进度由香色原生持有 | `LBLoadCurCpBridge` + 原版 `TextReadVC3` |
| 换源 | 章节匹配（精确→归一化→包含→相似度→索引兜底），换源接回进度 | `ChapterMatcher` + `BookBindingStore` |
| 发现 | `exploreUrl` + `ruleExplore`，结果走搜索通知 | `RuleWebBook.exploreBook` |
| 净化 | 书源 `replaceRegex` + 独立替换规则库 | `ReplaceEngine` + `ReplaceRuleStore` |
| 登录/Cookie | `loginUi` 走香色原版 WebView 登录页，Cookie 回灌后续请求 | `XiangseOpenWebView` 链 |
| 网页等待 | `startBrowserAwait` 可见页完成人机验证 | 香色 WebView |
| 变量/限速 | 源级 `variable`、JS put/get、并发限速 | LegadoRuleCore |

### 不做的（例外清单，只登记不开发 —— `legado-feature-exceptions.md`）

- `ruleReview` 书评/评论（引擎无实现）
- 听书 / TTS（无播放引擎与 AVAudio 链路）
- `coverDecodeJs` 封面解密（显示未解密封面或占位图）
- `bookVariable`（用源级 `variable` + JS 变量替代）

### 不做成什么样（形态红线）

- 不自建阅读器、不自建排版引擎；正文必须进原版 `TextReadVC3` 内核。
- 不用 overlay/probe 冒充上屏；Release 无 overlay，原生绑定失败时明确 fail-open。
- 用户可见文案不出现「Legado」品牌字（内部类名/日志可保留）。

## 四、已冻结决策

1. **Legado 协议只当书源数据后端**；阅读/书架/搜索/目录 UI 一律香色原版，不自建平行 UI。`LBLegadoCatalogListVC`/`LBLegadoSourceManagerVC`/UIAlert 导入是**过渡形态**桥接页（因原版链杀进程/污染风险而设）；**2026-07-26 用户决策：测试成功（G6/`72a6ed8`）后用香色原版组件替换它们——「用香色的 UI 而不是还原」，即阶段七**。
2. **接入缝是恢复原版 `loadCurCp` 生命周期**，只替换正文数据/缓存提供边界；禁止手工构造私有阅读 UI（`object_setIvar` 拼 TextReadTV 的老路已封存于 `archive/native-reader-experiments-b492825`）。
3. **overlay 仅 Debug IPA 可用**；Release 禁止 overlay，失败时 fail-open 不冒充。
4. **类/selector 归属以「原版 TXT vs Legado 同相位差分」为第一证据**；字符串邻近只是搜索手段不是证据。
5. **总验收只开一次**（开工资格已批准，已在推进）；阶段七（原生 UI 接管）与其**并行独立、互不阻塞**；总验收 UI 相关项以接管后形态**再抽验**，避免验过渡形态充数（`deferred-full-verify.md`）。
6. **例外清单四功能只登记不开发**（见第二节）。
7. **单一生产代码集成代理**；其余代理只产证据/工具，独立验证。
8. **删源语义默认 `keepBooksMarkUnavailable`**（保留书籍+标记不可用），待原版基线取证后再定是否改默认（`ios-mcp-acceptance.md` F 节）。
